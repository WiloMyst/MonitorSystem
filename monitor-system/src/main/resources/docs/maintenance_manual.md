### 《分行数据中心与网点设备智能排障手册 v2026版》

#### 第一章：核心机房设备与底层架构

**【故障码 ERR-DB-09】：核心交易数据库主从同步延迟异常**

**1. 故障定义与影响评估** 该故障码代表核心交易数据库（如 MySQL/Oracle 集群）的主节点与从节点之间的数据同步延迟时间，已连续 3 个采集周期超过系统设定的安全阈值（通常为 500 毫秒）。此故障可能导致网点前端查询业务出现“幻读”现象（即刚存入的款项无法立即查到），并在主库发生突发宕机时引发严重的数据丢失风险，属于 P1 级高危业务告警。

**2. 详细排查与处理步骤**

- **步骤一：网络链路与基础设施排查。** 运维人员需立即登录统一监控大屏（如 Zabbix 或 Prometheus 面板），检查主备数据中心之间的 BGP 专线网络带宽使用率是否已触及 95% 以上的满载红线。通过执行网络诊断工具，排查是否存在底层丢包或极高的网络抖动。若确认为流量洪峰导致的物理拥塞，需立刻联系网络组执行 QoS 策略，优先保障数据库同步端口的报文通行。
- **步骤二：数据库线程与负载诊断。** 授权人员需通过堡垒机登录只读从库，通过执行原生状态查询命令，重点核查同步线程运行状态。检查是否存在由于大批量 `INSERT` 或 `UPDATE` 引起的长事务阻塞了 Relay Log 的回放。同时检查服务器本地的磁盘 I/O 性能（iostat），确认是否因硬件瓶颈导致写入缓慢。
- **步骤三：业务紧急降级与流量调度。** 若判定延迟在 10 分钟内无法通过系统自愈恢复，必须立即在微服务网关层触发降级熔断预案。通过配置中心（如 Nacos/Apollo）下发指令，阻断所有非核心查询业务（如：历史明细分析、大数据报表批量导出），将必要的只读流量临时路由至主库，以此保全核心账务交易的绝对一致性。
- **步骤四：根因审计与事件定级。** 故障缓解后，需提取发生时段的慢查询日志（Slow SQL Log）进行自动审计，定位是否由于某项发版引入了未经索引优化的劣质 SQL。整理完整的事件时间轴与系统快照，派发深度排查工单至总行架构团队。



#### 第二章：网点终端设备与边缘计算节点

**【故障码 ATM-NET-OUT】：分行智能柜员机网络脱机告警**

**1. 故障定义与影响评估** 该故障码表示部署在物理网点的智能柜员机（ATM/VTM）与分行前置机之间的心跳包连续 5 次发送失败，设备已完全脱离管理网络。脱机状态下的终端将无法受理任何涉及核心账务的存取款及转账业务，直接影响客户体验并可能引发网点客诉，属 P2 级服务中断告警。

**2. 详细排查与处理步骤**

- **步骤一：逻辑网络与端口状态探测。** 远程登录分行 IT 运维管理系统，向故障终端 IP 发送 ICMP 探测包确认网络可达性。随后，通过 SSH 协议登录该终端所属的网点边缘交换机，查看对应接入端口的 MAC 地址表与链路状态（Link Up/Down）。若端口处于僵死状态，尝试下发指令重启该端口的 PoE（以太网供电）模块，进行终端硬重启。
- **步骤二：安全隧道与加密链路核查。** 智能终端均通过 IPSec VPN 隧道与分中心通信。需登录网点级 VPN 安全网关，检查 IKE 协商阶段是否失败，或者 SA（安全关联）生命周期是否异常过期。若发现密钥交换报错，需重置隧道的预共享密钥并强制重新发起协商请求。
- **步骤三：动环系统与物理环境联动确认。** 调取该终端所在区域的视频监控画面与动环系统数据，确认是否发生区域性停电、施工导致的网络光纤被挖断，或是设备遭到人为恶意破坏。
- **步骤四：现场工单派发与备件替换。** 若所有远程技术手段均无法恢复通信，证明极大概率为硬件损坏（如网卡烧毁或线缆脱落）。系统需自动生成现场抢修工单，并附带故障排查记录派发给最近的驻点外包运维工程师，要求其携带备用网络模块与测线仪，在 SLA 规定的 2 小时内到达现场进行物理抢修。



#### 第三章：基站与通信设备底层硬件

**【故障码 5G-BS-TEMP】：5G 宏基站 BBU 核心计算单元高温预警**

**1. 故障定义与影响评估** 该故障码由基站内部的温度传感器触发，表明基带处理单元（BBU）的内部环境温度已飙升至 85℃ 的危险临界点之上。持续的高温将引发芯片热发热保护机制，导致基站运算性能骤降、通信信道大面积阻塞，严重时可能引起主板烧毁甚至引发机房火灾，属极其危险的 P0 级硬件致命告警。

**2. 详细排查与处理步骤**

- **步骤一：热管理系统的远程紧急接管。** 值班人员应第一时间介入基站的环境控制总线。向基站机柜下发最高级别的散热指令，强制启动所有备用轴流风机至全速（100% PWM）运转状态。同时，若基站配备有独立的精密空调系统，需远程下调制冷温度设定点，并加大冷风送风量。
- **步骤二：发射功率限制与业务卸载。** 为了从源头减少发热量，需登录无线网管系统（NMS），启动高温降载预案。通过软件配置强行降低基站 RRU 的射频发射功率 20%-30%，限制最大并发连接数。同时，触发周边相邻基站的协同覆盖机制，将该高温基站覆盖范围内的部分移动终端平滑切换（Handover）至其他健康基站，实现流量泄洪降温。
- **步骤三：动环全量数据比对与消防联动评估。** 迅速核对动环监控平台上传送的其他传感器数据，包括：机柜湿度、烟雾浓度探测器状态、门禁开合记录等。如果温度曲线呈现非线性的急剧攀升，且伴有烟雾报警（Smoke Sensor = Active），必须立刻判定为极高火灾风险。
- **步骤四：极速切断市电与消防干预。** 若步骤三确认触发消防阈值，必须彻底放弃设备保全原则，立即远程下达指令切断基站的主供电回路（包括市电输入与蓄电池放电回路），防止灾情扩大。随后系统需自动对接属地消防应急平台进行告警推送，并指派现场维护团队携消防器材火速前往现场进行灾后损失评估。
